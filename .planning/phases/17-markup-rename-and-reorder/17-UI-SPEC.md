# Phase 17 — UI Design Contract

> Visual and interaction contract for **Markup Rename and Reorder** (CLMC Takeoff App — Windows Electron takeoff app). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a **mature app (16 phases shipped)**. This contract **extends the existing dark VS-Code-palette design system** — every value below is derived from `src/renderer/src/lib/constants.ts` (`COLORS`), `base.css`, and the named components. **No new design system, no new tokens, no Tailwind config.** Where a value is a sensible extension not literally present today, it is labelled `default (existing system)`.

60 / 30 / 10 split (existing dark theme — unchanged this phase):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | **#1a1a1a** (`COLORS.dominant`) | Workspace / canvas background; **input field backgrounds** (all text inputs sit on dominant) |
| Secondary (30%) | **#252526** (`COLORS.secondary`) | Right totals panel, Estimate grid, **context menus, modals/dialogs, the collision popover** |
| Accent (10%) | **#0078d4** (`COLORS.accent`) | See reserved-for list below. Hover `#1a86db`, active/press `#0067b8`. |
| Problem / block | **#dc2626** (`PROBLEM_RED` — `MARKUP_PALETTE[0]` red-600) | The rename **collision block** message only. **Not** a `COLORS` token: reuse the existing named-constant convention from `BlockedCommitMessage.tsx` (a local `const`, so the "COLORS-tokens-only" rule is not violated). |
| Soft validation | **#e8a838** (`COLORS.warning`) | Amber field-validation prompt (existing `MarkupNamePopup` "Enter an item name"). Not expected this phase — blank-name rename cancels silently (see §Inline Rename). |

**Accent (`#0078d4`) reserved for — THIS phase (explicit list, never "all interactive elements"):**
1. The **drag insertion line** (drop-position indicator) — 2px accent bar.
2. The **active inline-rename input border** (1px accent while the field is focused/editing — doubles as the focus ring).
3. The **Move / Copy dialog primary confirm button** (`background:accent`, hover `accentHover`, press `accentActive`, text `textOnAccent`) — mirrors every existing confirm button (`SaveCloseModal`, `DefaultMarkupChangeModal`, `MarkupNamePopup`).
4. *(Inherited, unchanged)* cycle-dot, selected autocomplete item left-border, selected color swatch.

**Accent is NOT used for:** the grip handle (→ `textSecondary`), context-menu items (→ transparent, hover `hoverSurface`), the grabbed/lifted row (→ `activeSurface`), the copy/duplicate "new row" flash (→ `activeSurface`), or the collision message (→ problem-red).

**Destructive:** **there are no destructive actions in this phase.** Rename **blocks** (no data change) on collision; Move/Copy/Duplicate are additive and each is a single-`Ctrl+Z` reversible command (SPEC §Undo atomicity). No delete, no destructive confirmation dialog. The problem-red `#dc2626` is used purely as the **blocking-validation** accent on the collision message, exactly as `BlockedCommitMessage` uses it for a refused commit.

## Interaction Contracts

### 1 — Group context menu (both surfaces) · D-01

Reuse the `TotalsRowContextMenu` container recipe **exactly**:

- Container: `position:fixed; left:x; top:y; minWidth:180; padding:8; background:secondary; border:1px solid border; borderRadius:4; boxShadow:'0 4px 12px rgba(0,0,0,0.4)'; zIndex:30; display:flex; flex-direction:column; gap:6; fontSize:13; color:textPrimary`. *(minWidth 180 to fit "Copy to…" / "Move to…"; the current file uses 160 — widen to 180 to match `MarkupContextMenu`.)*
- Section label row: `fontSize:12; fontWeight:600; color:textSecondary` — text **"Item"** (kept from today).
- Menu item (`role="menuitem"`): `width:100%; height:28; padding:'4px 8px'; background:transparent; border:none; borderRadius:4; color:textPrimary; fontSize:13; fontWeight:400; textAlign:left; cursor:pointer`. Hover → `background:hoverSurface`; leave → `transparent`.
- Separator: `<div style={{ height:1, background:border, margin:'4px 0' }} />` (from `MarkupContextMenu`).
- Dismissal recipe (copy verbatim): deferred listener registration (`setTimeout(…,0)`), outside-`mousedown` close, `Escape` close.

**Item order (locked to D-01 wording), top → bottom:**

Totals-panel row:
```
Item                (section label)
Rename
Move to…
Copy to…
Duplicate
──────────           (separator)
Copy as text        (totals-only)
```
Estimate-sheet row: the same four items (no "Item" label needed, but keep for parity is fine), **no** "Copy as text".

**Ellipsis convention:** `Move to…` and `Copy to…` carry a trailing ellipsis (they open a dialog). `Rename` (opens inline editor) and `Duplicate` (immediate, no dialog per D-08) carry **no** ellipsis.

### 2 — Inline rename · D-02 / D-03

Reuse the **uncontrolled-input + native-listener** recipe (`EstimateRow.tsx:184-247` / `TotalsRow` rate cell): `defaultValue` seed, native `blur`+`keydown` (Enter) commit, `stopPropagation` on `click`/`mousedown`/`keydown`. **Do not** use React `onChange`/`onBlur` (React 19 value-tracker + focusout semantics — documented in `EstimateRow`).

**Trigger:** menu "Rename" **or** double-click the name cell.
- Totals row: guard the double-click with `e.detail === 2` so the instant single-click cycle/arm is never delayed (D-02 — perceived performance is load-bearing per MEMORY).
- Estimate row: the Item cell has no click handler; double-click is clean (D-02).

**Visual (the input replaces the name cell in place; chip / quantity / uom stay put):**

| Property | Value | Source |
|----------|-------|--------|
| height | **22px** | `EstimateRow` input geometry (fits the 28/30px row) |
| padding | `0 6px` | `EstimateRow` input |
| background | `dominant` (#1a1a1a) | all app inputs sit on dominant |
| border | `1px solid` **`accent`** while editing (focus ring) | accent-as-active convention; falls back to `1px solid border` if not focused |
| borderRadius | **4** | canonical text-input radius (`MarkupNamePopup` name field) |
| color | `textPrimary` | — |
| fontSize | **13**, weight **400**, `textAlign:left` | matches the label text it replaces (13/400) — **not** the 12px right-aligned numeric cell style |
| outline | `none` | app convention (border carries focus) |

**Behaviour:** auto-focus + select-all on open. **Enter / blur commit**; **Esc cancels** (revert to original name). **Blank / whitespace commit → cancel silently** (revert, close editor) per D-03 "blank names rejected" — no amber prompt in the dense row. On a non-colliding commit, one undoable command renames every markup in the group + re-keys `rates` / `hiddenItemNames` (SPEC Req 1 — not a UI concern, but the editor must stay open until the store confirms no collision, then close).

### 3 — Rename collision block · D-04

On an attempted commit whose `name|type` already exists on **another** group of the same type: **block** — no store write — and show an inline message; the input **stays open, focused, and keeps the typed text**.

Copy (locked, D-04): **`A group named '{name}' already exists`** (substitute the typed name).

Styling — **modeled on** `BlockedCommitMessage.tsx` (the app's established block surface). The `padding` / `maxWidth` below are intentionally **more compact** than `BlockedCommitMessage`'s canvas-anchored `12px 16px` / `320` — this popover sits inline under a dense list row:

| Property | Value |
|----------|-------|
| element | `role="alert"` `aria-live="assertive"` |
| placement | absolutely positioned **directly beneath the rename input**, `margin-top:4`, left-aligned to the input — so it does **not** reflow the row list |
| background | `secondary` (#252526) |
| border | `1px solid border` |
| borderRadius | 4 |
| boxShadow | `0 4px 12px rgba(0,0,0,0.4)` |
| padding | `8px 12px` |
| maxWidth | 260 |
| fontSize | 13, lineHeight 1.4 |
| text color | **`#dc2626`** (`PROBLEM_RED`), fontWeight 600 |
| zIndex | 30 (above rows, same layer as the context menu) |

**Dismissal:** the message clears when the user edits the name (types) or presses Esc (Esc cancels the whole rename). It re-appears on the next colliding commit attempt. No timer.

### 4 — Drag-to-reorder · D-09 / D-10 (both surfaces)

**Grip handle (grab origin — drag works ONLY from here, D-09):**

| Property | Value |
|----------|-------|
| glyph | lucide **`GripVertical`** |
| size | **14** (matches the existing hover-revealed `Plus` affordance in `TotalsRow`) |
| color | **`textSecondary`** (#808080) — same as `Plus` / `Lightbulb`; **never accent** |
| placement | **leading edge**, absolutely positioned inside the row's existing **16px left-padding gutter** (`left:1–2px`, vertically centered). Rendering in the gutter means it does **not** reflow row content (content still starts at 16px). |
| reveal | on **row-hover only**, same trigger as `Plus` (`bg !== 'transparent'`) — instant conditional render, no animated transition (match existing) |
| cursor | `grab` on the handle; `grabbing` while dragging |
| a11y | `role="button"`, `aria-label="Reorder {name}"`, `tabIndex` optional |

**Lifted / grabbed row (D-10):** while dragging, the source row:
- `background: activeSurface` (#37373d — the existing pressed/active surface, so it reads as "picked up"),
- `opacity: 0.9`,
- `boxShadow: '0 4px 12px rgba(0,0,0,0.4)'` (menu-level lift),
- `borderRadius: 4`,
- follows the cursor on the Y axis only (constrained to its category — reorder is **within-category only**, D-11 / cross-category is Move).

**Insertion line (drop indicator, D-10):**
- a **2px** high `<div>`, `background: accent` (#0078d4), `borderRadius: 1`,
- rendered **between** the two rows at the drop boundary,
- **inset 16px** on both ends (aligned to the row content's left edge — matches `padding:'0 16px'`), spanning the remaining row width,
- `pointer-events:none`, drawn above the rows.

**Mechanism (research pick — CONTEXT "Claude's Discretion"): pointer-events, not HTML5 native DnD.** Rationale under the constraints (no new npm packages; a leading-edge handle; a controlled insertion-line; a possibly-scrolling list on both surfaces): the app already owns a proven window-level pointer-drag idiom — `useDraggable.ts` (which `setPointerCapture`s on `pointerdown`) and `Splitter.tsx` both drive the drag lifecycle off `window` `pointermove`/`pointerup` listeners. Reuse it: `pointerdown` on the grip → `pointermove` on `window` computes the drop index from pointer-Y vs each sibling row's vertical midpoint → `pointerup` commits one reorder command. HTML5 native DnD gives poor drag-image control, no clean insertion-line, and janky auto-scroll — reject it. (Final wiring is the planner/executor's; this is the contract the visuals assume.)

**Scope:** the handle + drag + insertion line behave identically on the **totals panel** and the **Estimate sheet** (a dense 10-column grid, `gridTemplateColumns: 'minmax(120px,1fr) 64px 48px 88px 88px 80px 72px 80px 80px 80px'`, `height:30`, that can scroll). Same tokens, same behaviour, both surfaces.

| title | `fontWeight:600; fontSize:14` | modal recipe |
| field label | `display:block; fontWeight:600; margin-bottom:4` — text **"Category"** | `MarkupNamePopup` |

**Copy — auto-name preview line (D-07, locked "no surprise"):** a body line **above** the Category field:

> Copy as **'{autoName}'** into…   *(e.g.* Copy as **'Slab (2)'** into…*)*

`{autoName}` = first-free `"{name} (n)"`, rendered inline at `fontWeight:600` (matches the `<strong>` emphasis used in `DefaultMarkupChangeModal`'s body). Rest of the line at `fontSize:13`, `color:textPrimary`.

**Move — parallel body line** (no rename): `Move '{name}' to another category.` with `{name}` at `fontWeight:600`.

**Titles + confirm labels:**
- Move: title **"Move to category"**, confirm button **"Move Group"**.
- Copy: title **"Copy to category"**, confirm button **"Copy Group"**.
- Cancel button label **"Cancel"** on both.

*(Confirm labels use verb+noun — "Move Group" / "Copy Group" — to match the app's own `DefaultMarkupChangeModal` "Change markup" precedent, per the UI-checker's Dimension-1 recommendation. The dialog title + body already disambiguate, so the noun is reinforcement.)*

Focus order: the **category input** auto-focuses (so the user types immediately). Enter confirms **unless** the autocomplete has a highlighted row (then Enter selects it — the guarded path).

### 6 — Duplicate + copy/duplicate feedback · D-07 / D-08

- **Duplicate (D-08): no dialog.** Menu "Duplicate" creates the `"{name} (n)"` snapshot in the **same** category with a fresh blank rate, immediately (one undoable command). No confirmation.
- **Copy:** after the Move/Copy dialog Confirm, the `"{name} (n)"` snapshot lands in the chosen category (appended to that category's manual order).

**Post-create feedback (silent per CONTEXT — no toast):**
- The newly created row (which appends to the **end** of its category's manual order) is **scrolled into view** within its category if off-screen.
- It gets a brief **background flash**: `activeSurface` (#37373d) → `transparent` over **~600ms**. `default (existing system)` — reuses the `activeSurface` token and the parent-owned-lifecycle fade precedent (`PulseHighlight` / `ConfirmationToast`, both "pure presentational, parent owns dismissal, no internal timer"). No `Ctrl+Z`-blocking modal, no toast — the flash is the whole cue so the user sees the new `"{name} (n)"` row.

*(Rationale: SPEC/CONTEXT stress copy/duplicate "auto-name silently." The flash is a minimal, token-consistent "here it is" cue and is intentionally understated; it is a labelled default — the executor may drop it if the plan prefers pure silence, but scroll-into-view should stay so the appended row isn't missed on a long list.)*
